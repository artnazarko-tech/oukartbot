# Инструкции для Claude

Этот файл Claude читает автоматически в начале каждого чата с этим репозиторием.
Здесь — всё, что нужно знать о проекте, и правила работы.

## О проекте

Telegram-бот для зарядной станции **Oukitel P2001E Plus**. Показывает заряд, вход, выход,
присылает отчёты по расписанию и уведомления (пропал/появился свет, низкий заряд, авария).

- Владелец: **artnazarko-tech** — учится программированию, это его первый проект.
- Подробно об устройстве: `docs/ARCHITECTURE.md`. Сервер и команды: `docs/SERVER.md`.
- Планы: `ROADMAP.md`. История изменений: `CHANGELOG.md`.

## Как устроено (кратко)

```
Станция (Wi-Fi) → облако Wonderfree → oukitel-portable-bridge → MQTT (mosquitto) → bot.py → Telegram
```

- Весь код бота — один файл `bot.py` (Python, python-telegram-bot 21, paho-mqtt 2).
- Запуск — `docker compose` (сервисы `mosquitto`, `bridge`, `bot`).
- Мост `oukitel-portable-bridge` — чужой проект. Его лицензия **запрещает распространение**,
  поэтому он не лежит в репозитории, а клонируется на сервере отдельно (`.gitignore`).

## Где работает и как обновляется

- Сервер: Hetzner Cloud CX23 (Falkenstein), Ubuntu 24.04, папка `/root/oukitel-bot`.
  IP и пароли — только у владельца, **в репозиторий не записывать** (репозиторий публичный).
- **Деплой автоматический:** push в `main` → cron на сервере каждые 5 минут запускает `update.sh`
  → `git reset --hard origin/main` → `docker compose up -d --build`.
- У Claude **нет прямого доступа к серверу**. Если нужно что-то сделать на сервере
  (логи, перезапуск, правка `.env`) — дать владельцу готовые команды с объяснением.

## Правила работы

1. **Общение — на русском.** Тексты внутри бота (кнопки, сообщения) — **на украинском**.
2. **Объясняй.** Владелец учится: после каждого изменения коротко и простыми словами объясни,
   что изменилось и почему. Предлагай, где он может попробовать сам.
3. **Перед большой задачей** — короткий план и уточняющие вопросы. Мелочи — делай сразу.
4. **Секреты никогда не коммитить:** `.env`, `config.json`, токены, пароли, IP сервера.
   Новые настройки — через переменные в `.env` + пример в `.env.example`.
5. **Проверяй перед push:** минимум `python3 -c "import ast; ast.parse(open('bot.py').read())"`,
   лучше — симуляция функций (см. примеры в истории: подмена `update`/`context` через `unittest.mock`).
   Помни: push в `main` = обновление на сервере через ≤5 минут. Сломанный код сломает бота.
6. **После каждого изменения обнови документацию:**
   - `CHANGELOG.md` — всегда (дата, что изменилось, понятным языком);
   - `ROADMAP.md` — отметь сделанное, добавь новые идеи;
   - `docs/ARCHITECTURE.md` / `docs/SERVER.md` / `README.md` — если поменялось устройство или команды.
7. **Коммиты** — на русском, по смыслу («Добавлены пользователи»), одно изменение — один коммит.
8. **Обратная совместимость:** файл `data/schedules.json` на сервере хранит настройки пользователей —
   при изменении его формата добавь миграцию, не теряй данные.
