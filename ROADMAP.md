## 🚧 В работе: версия 2 (ветка `dev`)
Работаем в ветке `dev`, в `main` переносим по готовности каждого этапа (сервер обновляется только от `main`).

1. [x] Устройства, пользователи, роли (админ / власник / гість — по каждому устройству), приглашения; миграция `schedules.json`
2. [x] Меню: Стан / Керування / Сповіщення / Статистика; «Стан» и «Детальний стан»
3. [x] Сповіщення по каждому пользователю и устройству (по умолчанию все выключены): свет появился/пропал (с длительностью),
       станция заряжена (без спама), заряд N% (порог настраивается), ошибка, нет данных 5 мин;
       вечерний итог (вкл/выкл + время) — сделаем вместе со статистикой (этап 5)
4. [x] Керування: AC / DC / USB вкл-выкл (по одному действию, следующее — после подтверждения от станции), лимит зарядки, подтверждение при выключении под нагрузкой
5. [x] Статистика: сегодня / неделя / месяц (вход, выход, отключения света, макс. мощность, среднее время зарядки), SQLite; итог дня (вкл/выкл + время)
6. [ ] Станции родных: отдельный мост на каждый аккаунт, логин/пароль вводятся только на сервере (не через Telegram)
- **Сеть:** флага AC-входа нет; определяем по входу/нагрузке/заряду (см. CHANGELOG). Если в коде моста есть неопубликованный тег
  напряжения/частоты AC-входа — можно попросить показывать его и определять сеть точно.
- **Выяснено про мост:** он отдаёт `temperature`, `output_frequency`, `ac_switch`, `dc_switch`, `ac_charging_limit` и др.,
  но **нет** «режима ДБЖ» и флага AC-входа (свет определяем по `ac_input_watts`). Мост берёт только **первое** устройство
  аккаунта (`devices[0]`) — для каждой станции нужен свой аккаунт и свой мост. Станции родных можно расшарить
  (в приложении есть sharing по e-mail/QR) на отдельный «технический» аккаунт — тогда их пароли не нужны.
7. [ ] Идеи: оценка автономности, график заряда, сценарии (заряд < N% → выключить AC), экспорт статистики
